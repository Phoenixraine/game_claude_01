## 3. Как работать
* Одна задача = ветка `claude/task-0NN-…` от актуального `main` → PR в `main`. **Не смешивай задачи в одном PR и не лезь в чужие папки.**
* Начинай с плана в описании PR (черновик), в конце обнови описание: **что сделано / какие команды реально запускались и что вывели / что не проверено / известные слабые места / что должен сделать владелец локально**.
* **Смотри на результаты.** Для картинок (превью, рендеры, макеты) открывай PNG и критикуй собственный результат; если выглядит плохо, исправляй, а не сдавай. Для кода — запускай тесты, санитайзеры (`-fsanitize=address,undefined`), g++ и clang++ (`-std=c++17 -fno-exceptions -fno-rtti -Wall -Wextra -Werror`).
* Не симулируй результат. Если что-то нельзя запустить (например, `bpy` не ставится) — прямо напиши в PR «не запускалось» и объясни, чем заменил проверку (чистый Python-тест с мок-объектами и т.п.). Это лучше красивого, но неподтверждённого отчёта.
* Детерминизм: те же сид + ввод → тот же результат (хэш). Никаких `std::random_device`, системного времени, неупорядоченных контейнеров в выводе.
* Размеры: бинарники и PNG ≤ 5 МБ (лучше ≤ 1 МБ); крупные модели не коммитить — коммитить скрипты и маленькие превью; если вывод большой — положить в `out/` и описать команду генерации (и `.gitignore`).
* Контракты имён/форматов, которые я подключаю в Unreal (имена объектов, пустышек, ключей JSON, значений `EventType`) — **стабильны**: если меняешь, пиши в README задачи и в PR отдельным пунктом «Изменение контракта».
* Всегда пиши README (RU) своей папки: как запустить, форматы, как подключить в Unreal, ограничения.
* Не трать усилия на бесполезное: не переписывай чужие модули «для красоты», не добавляй зависимости, не делай свои «улучшения питча», не рисуй UI-карточки и читаемый английский текст на HUD, не создавай аккаунты, не обращайся к внешним сервисам.
* Если ТЗ неоднозначно, выбери разумный вариант по умолчанию, зафиксируй его в PR и иди дальше (владельца нет онлайн). Один вопрос на PR допустим, но **не блокируйся**.
