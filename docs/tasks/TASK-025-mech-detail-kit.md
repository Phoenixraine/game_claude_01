# TASK-025 — Набор накладных деталей для мехов («супердетализация») и отрывающиеся части (Blender, `art/mech_detail/`)

**Ветка:** `claude/task-025-mech-detail` → PR в `main`. **Область:** `art/mech_detail/` (папки `art/mech/` и `art/mech_v2/` только читать).
**Читать:** `docs/STATUS.md` §5–6A, `docs/art/DESIGN_BIBLE.md`, `docs/art/refs/ref01_player_mech_sheet.png`, `ref02_enemy_mech_sheet.png`, `art/mech/README.md` и `art/mech/hy_rig.py` (контракт 19 костей, ориентация, UV/вершинные цвета), `docs/tasks/TASK-013-mech-v2.md`.

## Контекст
В игре меши мехов генерирует Hunyuan3D (локально), потом `hy_rig.py` их чистит и скиннит на 19 костей. Они «мыльные»: форма есть, мелких деталей нет. Владелец требует «супердетализацию, приложи усилия».
Облако не может запустить Hunyuan3D, зато может **построить библиотеку накладных деталей (greebles и функциональные узлы)**, которые я (локально) наклею на кости/зоны меша. Модульный подход: деталь = отдельный меш + якорь + кость-родитель + зона ядра.

## Что сделать
1. **Библиотека деталей** (`art/mech_detail/build_kit.py`, `bpy` + общий `art/common/bmb.py`, сид-воспроизводимо), единицы — метры, рост меха 82 м (детали масштабируются под него, смотрите габариты в `art/mech/README.md`):
   - Гидроцилиндры (шток+гильза+кожух, 6 размеров, хромированный шток/латунные муфты) — для плеч, локтей, колен, бёдер; пара «поршень внутри ноги» с гофрой;
   - Броневые плиты наружные (накладные) нескольких форм (клиновидные, ступенчатые, с рёбрами жёсткости, с болтами), вариации износа, «отрывающиеся» версии отдельными объектами `Plate_<zone>_<n>` (для эффекта отлёта кусков);
   - Шланги/кабели (кривые → меши) с муфтами; вентиляционные решётки, радиаторы, выхлопные трубы (сопла, окружённые рёбрами), охлаждающие вентиляторы (лопасти), антенны, сенсорные кластеры, прожекторные блоки, габаритные огни (пустышки `Lamp_<n>` с цветом);
   - Сочленения: шарниры плеч/локтей/коленей (шарнирные чаши, манжеты-гармошки), накладки-«юбки» таза, колпаки;
   - Шильдики и полосы маркировки (без читаемого текста; геометрические символы), номера-цифры бортовые (3 цифры из меша, набор 0–9);
   - Заклёпки/болты/швы: вариации «полоса болтов» на сплайне, «сварной шов» (меш на кривой).
   Бюджет: библиотека ≤ 1.2 млн треугольников, деталь ≤ 5000; на мех в сборке ≤ 600 000.
2. **Схема размещения** `art/mech_detail/placement_player.json` и `placement_enemy.json`: список инстансов {деталь, кость-родитель, локальная позиция/ориентация/масштаб, зона ядра (`Zone`), слой (`Armor|Mechanism|System`), группа «отрывается при `ArmorPlateLost`»}, ≥ 400 инстансов на мех;
   плюс скрипт `place_details.py`, строящий эти схемы **процедурно** на основе габаритов костей/зон (по модели скелета из `anim/rig.py`, а не по Hunyuan-мешу, которого в облаке нет), и скрипт-прикладыватель `apply_to_mesh.py` для локальной работы (берёт реальный FBX меха, по ближайшей поверхности подгоняет якоря —
   реализуйте и протестируйте на **синтетическом** меше-заглушке, пометьте «на реальном Hunyuan-меше не проверялось»).
3. **Дизайн-различие** игрок/враг: набор плейсментов и цветовых зон согласно `DESIGN_BIBLE` (игрок — тёплые маркировки, обтекаемее; враг — угловатый, красные сенсоры); `palette_mech.json`.
4. **Материалы-слоты**: `M_MechHull` (общий, уже есть в игре: вершинные цвета R выпуклость, G AO, B зона, A эмиссия — сохранить контракт, записать вершинные цвета в деталях по тому же правилу), `M_Chrome`, `M_Brass`, `M_Rubber`, `M_Emissive_Lamp`, `M_Glass_Sensor`.
5. **Отлёт кусков:** для каждой зоны `debris_<zone>_<n>.fbx` — 3–6 кусков-обломков брони с «оборванным» краем (заходит в паре с `Plate_*`), и `Dmg_<zone>` — меши повреждённого вида (вмятины/пробоины), которые можно подменять.
6. **Превью**: турнтейбл-листы (8 ракурсов) каждой категории; собранный синтетический «манекен» меха (капсулы по костям) с наклеенными деталями, 6 ракурсов; смотрите на PNG и исправляйте (сверяться с `ref01/ref02`). Экспорт: FBX/GLB по категориям (≤ 5 МБ на файл) в `art/mech_detail/out/`, `manifest.json`.
7. Тесты: нет вырожденных граней, нормали наружу, имена по контракту, бюджеты, детерминизм, плейсмент: детали не пересекают друг друга (≥ 90 % без перекрытия), зоны покрыты.
