# TASK-018 — Мини-игра взлома люка: логика, сложность, бот, спецификация экрана (`core/` + `data/hack/`)

**Ветка:** `claude/task-018-hack-minigame` → PR в `main`. **Область:** `core/include/iv/HackGame.h`, `core/src/HackGame.cpp`, `core/tests/test_hack.cpp` (модуль `Hack`), `data/hack/`, `docs/ux/hack_minigame.md`.
Выполнять **после или вместе с** TASK-017 (последовательно, одна ветка допустима; интерфейс согласовать — см. п. 6 TASK-017).

## Контекст
Во время абордажа (`docs/STATUS.md` §6B) игрок на весь экран играет в **сложную мини-игру на время**, взламывая входной люк вражеского меха у стыка плеча и руки.
Жанровые ориентиры владельца: **Zenless Zone Zero** (мини-игры-головоломки в стиле «сдвиги/сигналы/цепочки») и **Pragmata** (взлом: проводка пути по сетке узлов под давлением времени).
Мини-игра должна быть читаемой за 3 секунды обучения, но **трудной**: ошибка стоит времени, хорошее выполнение даёт `quality` (влияет на урон гранаты).
Управление: клавиатура/мышь **и** геймпад (без точного курсора; все действия доступны стрелками/WASD/стиком + 2–3 кнопки).

## Что сделать
1. **Ядро логики** (`iv::HackGame`, C++17, без Unreal, детерминированное, свой `Rng`): конфиг `HackConfig{difficulty 1..10, seed, timeLimitTicks, mistakePenaltyTicks, …}`; `Step(const HackInput&)`;
   состояние `Running/Success/Fail/Timeout`; метрики `progress 0..1`, `mistakes`, `quality 0..1` (по оставшемуся времени и ошибкам); `Reroll()` (новая раскладка после перелёта на другое плечо,
   с сохранением части прогресса — параметр).
2. **Три слоя в одной сессии** (каждый — отдельный «этап» взлома; на низкой сложности два, на высокой три+фаза-босс):
   a) **Прокладка пути**: сетка узлов (например 6×5, повёрнутые гексы или квадраты) с блокирами и «ледяными» узлами; провести цепочку от входа к ядру замка, не пересекая себя, подбирая
      «ключевые» узлы в заданном порядке (граф-путь; генератор должен **гарантировать решаемость**, возвращать эталонное решение и минимальное время);
   b) **Ритм/синхронизация сигналов**: 3–5 дорожек, по которым идут импульсы к зоне попадания; нажать нужные кнопки в окно (±N мс на сложность); пропуск = ошибка + штраф времени + «тревога» (ускорение);
   c) **Подбор частоты** (две вращающиеся шкалы/секторы): совместить сектор взломщика с окном защиты, окно сужается на каждом удачном ходе.
   Правило тревоги: накопленные ошибки повышают «температуру ICE»; при пороге этап перезапускается (штраф), а не мгновенный проигрыш.
3. **Калибровка** (`data/hack/difficulty.json`): таблица сложностей 1..10 → размеры, число блокеров, скорости, окна в мс, лимит времени (общий 25–60 с), штрафы. Сложность в бою = функция
   `(архетип врага, сложность ИИ, целостность зоны)`, формула в `HackGame::DifficultyFor(...)`. Все числа — в `Tuning.h` (раздел «Hack») или в JSON, который грузится из `core` **без** файловых операций
   (вшитая таблица в коде + проверка эквивалентности с JSON тестом).
4. **Боты для проверки** (`core/tools/hack_bot.cpp` или в тестах): «идеальный» (решатель), «хороший человек» (задержка реакции 180 мс, 3 % ошибок), «средний» (260 мс, 10 %), «плохой» (350 мс, 25 %). Прогнать по
   сложностям 1..10 × 200 сидов, построить таблицу вероятности успеха. Цель: хороший человек — 80–90 % на сложностях 1–3, 45–60 % на 6, 15–25 % на 9–10; идеальный — 100 % (иначе решаемость нарушена).
   Результат — `docs/ux/hack_calibration.md` с таблицей и графиком (matplotlib → PNG в `data/hack/previews/`, не более 1 МБ).
5. **Спецификация экрана** `docs/ux/hack_minigame.md` (RU): раскладка 16:9, зоны экрана, цвета (из `ui/palette.json`, если уже есть, иначе свои, зарегистрировать в `data/hack/palette.json`),
   анимации появления/успеха/ошибки/тревоги, звуки (список событий для аудио: `hack_tick, hack_ok, hack_err, hack_alarm, hack_stage_clear, hack_success, hack_fail` — согласовать с `audio/`),
   подсказки управления для KBM и геймпада, поведение при потере фокуса/паузе. Приложить **SVG-макеты** экранов (3 состояния) в `data/hack/mockups/` (рисуются кодом Python), PNG-превью. Без читаемых английских слов на экране, текст — по-русски кратко.
6. **Экспорт для Unreal**: `data/hack/hack_levels.json` — набор из 500 предгенерированных раскладок (по сложностям) со схемой `data/hack/schema.json`, чтобы UE мог проигрывать без портирования генератора; в игре всё равно
   используется `core` (генератор и валидатор детерминированы, тест: JSON == генератор при том же сиде).

## Тесты и приёмка
`core/tests/test_hack.cpp` (+ CMake-модуль `Hack`): решаемость каждой раскладки (500 × 10 сложностей), детерминизм, штрафы, тревога, таймаут, `Reroll`, граничные входы (2 кнопки одновременно, ввод после конца),
отсутствие исключений, `-Werror`. Отчёт в PR: команды и выводы, таблица калибровки, список непроверенного (в игре на экране не видно — это проверяется локально).
