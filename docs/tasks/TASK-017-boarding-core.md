# TASK-017 — Абордаж: крюк, взлом люка, граната, помеха-замах (ядро `core/`, C++17)

**Ветка:** `claude/task-017-boarding-core` → PR в `main`. **Область:** `core/` (новые файлы `Boarding.h/.cpp`, `HackGame.h/.cpp` — см. TASK-018; тесты `core/tests/test_boarding.cpp`; минимальные хуки в `Duel`/`Events`/`Types`/`Tuning`).
**Обязательно прочитать:** `docs/STATUS.md` §6B (дословное описание фичи от владельца), `docs/CORE_API.md`, `core/include/iv/*.h`, `CLAUDE.md` (правила ядра).

## Цель
Платформенно-независимая **машина состояний абордажа** — «правила и тайминги», без графики. Unreal потом проигрывает анимации по событиям.
Фича в игре: по одной кнопке пилот вылезает из кабины на плечо, стреляет крюком-кошкой во вражеский мех, высаживается у люка рядом со стыком плечо/рука,
взламывает люк мини-игрой на время (TASK-018), бросает гранату и улетает; граната взрывает ту часть тела врага. Враг может помешать замахом руки по плечу —
игрок должен вовремя перелететь крюком на другое плечо, иначе он убит (поражение). **Пока враг сам не умеет абордаж против игрока** (но API должно быть симметричным по `Side`,
а ИИ-ограничение — флагом в `Tuning`/`Boarding::Config`).

## Требования (контракт — менять имена нельзя без записи в `docs/CORE_API.md`)
1. `iv::Boarding` — отдельный объект, шаг `Step(Duel&, const BoardingInput&)` ровно на 1/60 с, собственный сид (`Rng`), детерминированный. Состояния
   (`enum class BoardPhase`): `Idle, ClimbOut, OnShoulder, HookLaunch, HookFlight, Landing, Hacking, GrenadeThrow, Escape, WatchBlast, ReturnHook, ClimbIn, Smashed (поражение), Done`.
   Длительности каждого этапа — **в `Tuning.h`** (мс → тики через `MsToTicks`), с комментарием «STATUS §6B».
2. Старт: `BoardingInput.start` (ребро). Запрещено, если: клинч, идёт замах/удар/ультимейт, оглушение, кулдаун, не хватает ресурса (энергия/стабильность — взять из `Resources`),
   у выбранного плеча зона `Destroyed/Severed`, бой окончен. Причина отказа возвращается кодом (`BoardingDenied`) — для UI-подсказки.
3. Пока пилот снаружи, **мех игрока на автопилоте**: `Boarding` переключает боец в режим `autopilot` (простая защитная ИИ-политика: блок/уклонение по телеграфам, не атакует,
   не тратит ультимейт). Реализовать как отдельный флаг бойца (`Fighter::set_autopilot`), использовать существующий `Ai` в «оборонительном» профиле. Через `ExternalHit` по игроку
   пилот в это время не гибнет, но получает «шок» → удлиняет таймеры (параметр).
4. Выбор цели: плечо врага `Zone::ShoulderL/ShoulderR` — люк у стыка плеча и руки. Если плечо уже `Destroyed` → люк на противоположной стороне. Голова — недопустимая цель.
5. **Помеха**: враг (`Side` ≠ владельцу абордажа) в фазах `HookFlight(посл. 30 %)/Landing/Hacking` может начать «замах по плечу» (`Swat`):
   телеграф `swatWindupTicks` (≥ 900 мс на лёгкой сложности, ≥ 600 мс на тяжёлой), затем удар в плечо, где сидит пилот. Телеграф публикуется событием
   `BoardingSwatTelegraph{side: левое/правое, ticksToImpact}` — в углу экрана будет «камера врага». Игрок обязан нажать `BoardingInput.swing` (ребро) в окне
   `[ticksToImpact - swingWindowTicks, ticksToImpact - swingMinTicks]` (слишком рано — крюк летит, но враг «подстраивается» — один раз, повтор; слишком поздно — смерть). Успех: пилот
   перелетает на другое плечо (`HookSwing`, ~900 мс), прогресс взлома: сохраняется доля `swingKeepProgress` (Tuning), мини-игра получает `Reroll()`. Провал:
   `Smashed` → `EventType::BoardingSmashed` → конец матча (`MatchEnd` с причиной = `PilotLost`; добавить `EndReason::PilotLost`).
   Частота помех: ИИ решает по архетипу/сложности (`Ai`-профиль, шанс/кулдаун в `Tuning`), максимум `maxSwatsPerBoarding` за заход, не в первые `swatGraceTicks` после посадки.
6. Взлом: интерфейс к `HackGame` (TASK-018): `Boarding` хранит экземпляр, пробрасывает `HackInput`, получает `HackResult{Success, Fail, Timeout}`.
   Провал/таймаут → `ReturnHook` → `ClimbIn`; штраф: потеря `penaltyEnergy`, мех игрока получил за время отсутствия урон по факту (нормальный `Duel`, бой идёт), плюс кулдаун.
7. Успех → `GrenadeThrow` (событие `GrenadeThrown`) → `Escape` (полёт вверх/в сторону, событие) → `WatchBlast`: **через `blastDelayTicks` взрыв** — вызвать
   `Duel::ExternalHit(enemy, shoulderZone_or_ArmZone, damage, stab, source=3 /*grenade, добавить в документацию*/, StatusKind::Burn, ticks)`. Урон/зона — в `Tuning`,
   зависят от `HackResult.quality` (быстрее/чище — сильнее, но не больше `kGrenadeDamageMax`; сопоставим с `kHeavyDamage = 17.5`: цель — примерно 1.5–2.2 тяжёлых удара). Если зона уже «сломана» —
   урон по слоям как у обычного удара. Затем `ClimbIn` → `Done` и возврат управления, кулдаун `kBoardCooldown` (не менее 45 с).
8. События (добавлять **в конец** `EventType`, порядок существующих — контракт): `BoardingStarted, BoardingPhase(a=BoardPhase,b=длит.тиков), BoardingDenied(a=причина), HookFired, HookLanded,
   HackStarted(a=сложность), HackProgress(value), HackResultEvt(a=Success/Fail/Timeout), BoardingSwatTelegraph, BoardingSwingOk, BoardingSmashed, GrenadeThrown, BoardingBlast(zone,value), BoardingEnded`.
   Обновить `docs/CORE_API.md` (новый раздел «Абордаж»: диаграмма состояний в mermaid/ASCII, таблица событий и тайминги).
9. Интеграция с `Duel`: пока идёт абордаж, обычный бой продолжается (мех на автопилоте), `Duel::Step` не должен ломаться; `Boarding` — внешний наблюдатель, вызывается после `Duel::Step`.
   Сериализация состояния для хэша: добавить `Boarding::Hash()`; тест детерминизма = равный хэш истории событий при равном сиде и вводе.

## Тесты (`core/tests/test_boarding.cpp`, модуль CMake `Boarding` — добавить в `foreach(module …)`)
Обязательные сценарии: старт отказан при клинче/ударе/кулдауне/ресурсах/уничтоженном плече; полный успешный заход (хак выигран ботом) → урон по врагу в нужном диапазоне;
провал хака → возврат без урона врагу; таймаут; помеха + вовремя нажатая кнопка → смена плеча, прогресс сохранён по `swingKeepProgress`; помеха без нажатия → `Smashed` + `MatchEnd`;
нажатие слишком рано/слишком поздно; плечо уничтожено во время захода; симметрия сторон (`Side::A`/`B`); детерминизм (2 прогона = равный хэш); автопилот не атакует и принимает блок/уклонение;
фаззинг: 2000 случайных вводов за 5 минут игрового времени — нет зависаний, `Boarding` всегда приходит в `Idle/Done`.
Запускать: `cmake -S core -B build && cmake --build build && ctest --test-dir build --output-on-failure` на g++ и clang++ (`-Wall -Wextra -Werror -fno-exceptions -fno-rtti`), плюс ASan/UBSan.

## Баланс-проверка
Расширить `ivsim`: режим `--boarding` (бот игрока использует абордаж каждые N с против 6 архетипов × 3 сложностей): частота успеха, средний урон, частота гибели от замаха, влияние на длительность матча.
Цель баланса (подбирать числа в `Tuning.h`): при «хорошем боте» успех ≥ 55 %, при «плохом» ≤ 20 %; смерть от замаха при правильно нажатой кнопке = 0; абордаж не должен быть доминирующей стратегией
(винрейт бота, спамящего абордаж, ниже винрейта бота-фехтовальщика). Отчёт — `docs/BOARDING_BALANCE.md` с таблицами.
