## Что нужно (дословные требования владельца)
«Отточи визуал внутри камеры робота. Сделай разные трубы, из которых идёт пар при движении, провода торчащие, кнопки, мониторы. **Большинство экрана занимает стекло**, через которое мы смотрим. На него выведи по углам разные штуки…
При ударах по нам я хочу чтобы всё реально прям тряслось, трубы рвались, провода рвались, появлялись пожары, везде ворнинг и красные огни.»

## Что сделать
1. **Скрипт `art/cockpit_v2/build_cockpit_v2.py`** (Blender 4.x, `bpy`; запускается `blender -b -P …` или `pip install bpy`; если `bpy` не получилось поставить — честно написать «не запускалось» и аккуратно проверять
   чистый Python-код тестами с замоканным `bpy`). Камера пилота в (0,0,0), взгляд вдоль −Y, метры — контракт TASK-003; экспорт FBX + GLB в `art/cockpit_v2/out/` (≤ 25 МБ суммарно; если больше — не коммитить, дать скрипт).
2. **Композиция кадра:** обзорное стекло занимает **≥ 70 % площади кадра** (проверка: рендер с камеры 90° FOV, 16:9, маска стекла → процент). Рамы тонкие, стойки не закрывают центр, по периметру — каркас, приборные
   пульты ниже линии горизонта, потолочная панель сверху, боковые пульты.
3. **Наборы деталей** (отдельные объекты с контрактными именами; префикс = класс, чтобы в UE ставить свой материал и логику):
   - `Pipe_<n>` — **не менее 40 труб/шлангов** (кривые → меши, 5–9 радиусов, с муфтами, хомутами, изоляцией, вентилями); у ≥ 12 из них — пустышки `SteamPort_<n>` (empty, ориентация = направление выброса) для частиц пара;
     `Pipe_Burst_<n>` — их «порванные» версии (раскрытый разрыв, лохмотья изоляции) как переключаемые варианты (скрытые коллекции) + пустышки `LeakPoint_<n>`;
   - `Wire_<n>` — **не менее 60 проводов** (толстые жгуты, одиночные, торчащие вверх из потолочных люков, висящие качающиеся) — полилинии с точками подвеса (`WireAnchor_<n>`) для симуляции в UE, плюс `Wire_Snapped_<n>` варианты и `SparkPort_<n>`;
   - `Btn_<n>` (≥ 80 кнопок/тумблеров/рычагов/переключателей, 6 типов, без текста — символы/пиктограммы текстурой/нормалью), `Dial_<n>`, `Slider_<n>`, предохранительные колпачки;
   - `Mon_<n>` — **не менее 12 мониторов** разных форм (плоские, выпуклые ЭЛТ, узкие полосы, радар-круг), UV 0–1 каждый для динамических экранов, слот `M_Monitor`; пустышки `MonitorAnchor_<n>`;
   - `Lamp_<n>` ≥ 40 индикаторных ламп (слот `M_Lamp`, группы: `Lamp_Warn_*` (красные/оранжевые), `Lamp_Ok_*`), `AlarmBeacon_<n>` — 4 вращающихся маяка (ось вращения пустышкой), `StrobePanel_<n>`;
   - `Fire_Socket_<n>` — 8 точек возможных пожаров (пустышки) + `Scorch_Decal_<n>` — плоскости-декали под копоть;
   - `Glass_<Front|…>` — стекло с UV под капли/трещины; `Glass_Crack_Mask_<n>` — 4 текстуры-маски трещин (процедурно, PNG 1024², ≤ 1 МБ).
   Все объекты с корректными нормалями, масштабом 1:1, без не-однородных масштабов, каждая деталь ≤ 3000 тр., вся кабина ≤ 400 000 тр.
4. **Пайплайн степеней повреждений:** `cockpit_damage_spec.json` — список эффектов по уровням тяжести удара (S0 лёгкий … S4 катастрофа) с привязкой к именам: какие трубы рвутся, какие провода обрываются, какие лампы красные,
   какие монитор(ы) гаснут/глючат, какие `Fire_Socket` загораются, амплитуда/частота тряски. Согласовать с TASK-022 (`data/damage_fx/`) — читать оттуда, если файл уже есть, иначе создать общий формат и записать в README.
5. **Рендер-проверки (Cycles/Eevee, headless):** `art/cockpit_v2/previews/` — вид от первого лица (4 кадра: целая / S2 / S3 / S4 с огнём и красной подсветкой), вид «все пары и лампы подсвечены цветом по классам»,
   вид сверху-сзади, схема размещения. **Смотрите на PNG и исправляйте то, что выглядит плохо** (сравнивать с `ref03`).
6. **Контракт для Unreal:** `art/cockpit_v2/README.md` (RU) — таблица всех классов объектов/пустышек, как их находить (префиксы), какие материалы подставлять, что включать при каком уровне повреждений.
