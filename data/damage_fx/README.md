# data/damage_fx — реакции на повреждения (TASK-022)

Единые таблицы «событие ядра → тряска камеры, эффекты кабины, отлетающие куски, разрушение зданий, предупреждения» + эталонная реализация математики на Python (только стандартная библиотека) и тесты.
Unreal грузит JSON как таблицы (DataTable / JSON-ассет) и настраивает «сочность» без перекомпиляции; `fxmath.py` — эталон, по которому порт на C++ сверяется. Как это использует игра — `docs/ux/damage_fx.md`.

## Файлы
| Файл | Что внутри |
|---|---|
| `build_tables.py` | **Источник правды.** Генерирует все JSON (`python3 data/damage_fx/build_tables.py [каталог]`). JSON руками не правим: тест сверяет, что закоммиченные файлы = вывод генератора |
| `identifiers.json` | Все идентификаторы: 9 зон, слои, S0–S4, классы кабины и их **минимальное** число (контракт для TASK-020), граф `Fire_Socket_00..07`, осколки (контракт для TASK-016), типы кусков меха, id звуков |
| `shake_profiles.json` | Формула тяжести S0–S4, профили тряски для 35 типов событий, лимиты, направления по зонам/замаху |
| `cockpit_effects.json` | Что ломается в кабине на каждом уровне S0–S4, красный свет, сирена, голос, правила огня |
| `mech_chunks.json` | Куски меха по зоне × слою (броня/механика/система), баллистика, правила привязки к событиям |
| `building_destruction.json` | 5 сценариев × стадии (контакт → дробление фасада → обрушение → пыль), бюджеты, пыль и звуки |
| `warnings.json` | 16 предупреждений: триггер, приоритет, цвет, ритм мигания, звук, иконка HUD, голос |
| `global_tuning.json` | «Кнопки сочности»: глобальные множители и допустимые диапазоны |
| `coverage.json` | Какую группу эффектов получает каждый `EventType` ядра (ничто не забыто) |
| `fxmath.py` | `severity_for_event`, `shake_for_event`, `mix_shakes`, `plan_cockpit_effects`, `plan_fire_spread`, `red_light_curve`, `plan_chunks`, `simulate_chunk`, `plan_building_break`, `warnings_for_event`, `plan_for_event` |
| `validate.py`, `schema/*.schema.json` | Схемы (подмножество JSON Schema) и свой маленький валидатор: `python3 data/damage_fx/validate.py` |
| `make_previews.py`, `previews/*.png` | Графики (matplotlib; `python3 data/damage_fx/make_previews.py`) |
| `tests/test_damage_fx.py` | Юнит-тесты |

## Запуск
```
python3 data/damage_fx/build_tables.py          # пересобрать JSON
python3 data/damage_fx/validate.py              # схемы
python3 -m unittest discover -s data/damage_fx/tests    # из корня репозитория
python3 data/damage_fx/make_previews.py         # картинки
```
Python ≥ 3.8; matplotlib нужен только для картинок.

## Пример
```python
import sys; sys.path.insert(0, "data/damage_fx")
import fxmath as fx
ev = {"type": "HitEvent", "zone": "Reactor", "a": 2, "b": 5, "c": 0, "value": 45.0, "value2": 30.0}   # a = Layer, b = ZoneState, c = HitInfo flags
plan = fx.plan_for_event(ev, seed=4)       # severity, shake (кривые), cockpit (команды), chunks, warnings, state
```
Событие — словарь с полями `EventType` ядра (`type`, `zone`, `a`, `b`, `c`, `value`, `value2`); `c` для `HitEvent`: биты 0–1 = замах (Up/Left/Right/Down), бит 2 = блок, бит 3 = парирование.

## Детерминизм и ограничения
* Каждый план берёт `seed` и собственный `random.Random(str)`; одинаковый вход → побайтно тот же JSON. Системного времени и глобального ГПСЧ нет.
* Жёсткие лимиты (проверяются тестами по **всем** событиям × S0–S4 × 9 зонам): смещение камеры ≤ 12 см, поворот ≤ 4°, компоненты > 3.5 Гц ≤ 0.3 с, «уменьшить тряску» = ×0.25, затухание к нулю в конце. Лимитер мягкий (tanh) и применяется и к сумме нескольких тряск (`mix_shakes`).
* Куски: дальность ≤ 120 м (баллистика с сопротивлением считается и в плане, и в тесте), не залетают внутрь меха, начинают движение от оси тела.
* Здание: ≤ 400 крупных, ≤ 6000 мелких осколков, ≤ 80 дымовых «пуфов» — жёсткий потолок независимо от энергии и множителей.
* События 017 (`HookFired … BoardingShock`) описаны в таблицах, хотя в `core/include/iv/Events.h` ветки `main` на момент PR их ещё нет (они в PR TASK-017). Тест покрытия допускает именно этот набор.
* Координаты кусков/осколков — метры, ось Z вверх; позиции даны относительно меха (якорь зоны `ZONE_ANCHOR` в `fxmath.py`), в Unreal нужно сдвинуть на трансформ меха. Якоря зон — **оценка** по высоте меха 85 м, их надо сверить с реальными сокетами.
* Что НЕ проверялось: вид и «ощущение» в Unreal (амплитуды тряски, плотность частиц) — это настройка на стороне владельца через `global_tuning.json`.
