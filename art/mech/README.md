# art/mech/ — мех BASTION-01 (TASK-002)

Воспроизводимый скрипт Blender (`bpy`), который с нуля строит hard-surface модель меха **BASTION-01 высотой 82 м**, проверяет
контракт для Unreal Engine 5, прогоняет тесты поз и экспортирует результат. Никаких внешних ассетов: вся геометрия — код.

## Запуск

```bash
pip install bpy numpy scipy               # Blender как Python-модуль (проверено: bpy 5.0.1, Python 3.11)
python art/mech/build_bastion.py          # всё: сборка, UV, проверки, позы, FBX/GLB/JSON, превью (~9 мин на 4 CPU, из них ~7 мин рендер)
python art/mech/build_bastion.py --no-render          # без превью (~1 мин)
python art/mech/build_bastion.py --only=damage,scale  # перерисовать только часть превью (имена: front side back three_quarter damage scale pose_stand pose_swing_right pose_step)
blender -b -P art/mech/build_bastion.py -- --no-render   # то же через установленный Blender
```

Флаги: `--no-uv` (быстрый черновой прогон без развёртки; проверки UV пропускаются), `--no-render`, `--only=…`.
Скрипт **падает** (исключение/`SystemExit`), если нарушен контракт, не прошёл тест позы или повторный импорт FBX.

## Параметры

Все размеры — словарь `PARAMS` в начале `build_bastion.py` (метры): высоты суставов (`hip_z`, `knee_z`, `ankle_z`, `waist_z`,
`shoulder_z`, `elbow_z`, `wrist_z`…), разнос рук/ног (`arm_x`, `leg_x`, `shoulder_x`), положение головы и реактора, итоговая
высота (`height` — по ней строится верхушка сенсорной мачты). Геометрия зон — `lib/design.py`, примитивы и материалы — `lib/hs.py`.

## Контракт для Unreal (выполняется и проверяется скриптом)

- Метры; +Z вверх, мех смотрит в **−Y**, начало координат на земле между стопами (bbox: X −39,2…39,2; Y −18,7…22,7; Z 0…82,0).
  «Левая» сторона меха — это +X (кости `_l`). FBX: `axis_forward=-Y`, `axis_up=Z`, `apply_scale_options=FBX_SCALE_UNITS`, масштаб 1.0,
  без leaf-костей и анимации.
- Арматура `BASTION_Rig`, ровно 19 костей: `root, pelvis, torso, head, reactor (child of torso), shoulder_l/r, upperarm_l/r,
  forearm_l/r, hand_l/r, thigh_l/r, shin_l/r, foot_l/r`. Головы костей — в реальных точках вращения.
- Каждая деталь — отдельный объект, одна вертексная группа с именем кости, вес 1.0 на всех вершинах, Armature-модификатор.
- Имена: `Body_<bone>`, `Armor_<Zone>_<NN>`, `Inner_<Zone>_<NN>`, `Joint_<bone>`, `Cable_<Zone>_<NN>`;
  зоны: `Head, Torso, Reactor, ShoulderL/R, ArmL/R, LegL/R`.
- Материалы (8 слотов, имена фиксированы): `M_Graphite, M_CeramicGray, M_DarkMetal, M_Hydraulic, M_AccentOrange, M_Rubber,
  M_Glass_Sensor, M_Emissive_Status`. Principled BSDF с PBR-значениями; цвет «в геометрию» не зашит.
- UV у всех объектов; бюджет ≤ 450 000 треугольников; без нулевых граней и n-gon'ов (крышки цилиндров триангулируются),
  положительный объём (нормали наружу).

Пластины стоят на 1,3–1,8 м над **замкнутой** оболочкой `Body_*`; в зазоре лежит механика `Inner_*`/`Cable_*`, поэтому любую
`Armor_*` можно убрать без дыры (см. `preview_damage_arm.png`).

## UV

На каждый объект: `smart_project` (угол 66°, острова по углу, не авто-куб) → выравнивание масштаба островов → упаковка без
вращения с отступом. Затем все UV масштабируются к **одинаковой плотности текселей** на всех 241 объектах
(0,012149 единиц UV на метр; разброс 1,000, проверяется ≤ 5 %): плотность задаёт самый большой объект (оболочка торса), поэтому
мелкие детали занимают малую часть квадрата 0…1. Перекрытий островов нет (проверка: пробные точки каждого UV-треугольника не
попадают в чужие треугольники, ≤ 0,5 %; получено 0 %). Для текстурирования это значит: масштаб тайлящихся материалов
согласован по всему меху, а уникальные текстуры/маски нужно собирать в атлас (TASK-008) — файл UV сам по себе одну текстуру
на деталь не заполняет.

## Позы и суставы

`out/BASTION_01_pose_tests.json`: допустимые углы суставов (град., вокруг мировых осей через сустав, относительно родителя) и три
позы — `stand`, `swing_right` (замах правой рукой сверху с поворотом корпуса), `step` (левая нога вперёд). Скрипт ставит позу
на арматуру, берёт деформированные меши и проверяет, что у деталей не соседних костей нет проникновения глубже 0,5 м
(вершины одной детали внутри выпуклой оболочки другой). Результат: **0 столкновений** в трёх позах (на ранних итерациях
находились: кисть в наколеннике — разведены руки; предплечье в торсе при замахе — уменьшен подъём и добавлен отвод).
Превью: `preview_pose_*.png`.

## Что проверено и что нет

Проверено запуском: сборка с нуля без интерактива; контракт (кости, имена, материалы, веса, UV, бюджет, размеры, ориентация,
нормали); повторный импорт FBX в пустую сцену (19 костей, 241 меш, высота 82,00 м, +Y = спина); три позы; все превью
отрендерены и просмотрены.

**Не проверено:** импорт в Unreal Engine (скелет, Nanite, материалы), `blender -b -P` с настоящим бинарным Blender (проверялся
модуль `bpy` 5.0.1; на Blender 4.x возможны отличия API `bmesh.ops.bevel`/экспортёров), реальный texel-density в UE, анимация.

Эстетика (честно): это чистая «заготовка под текстурирование», а не фотореализм ключевого арта — формы угловатые, плоские
пластины с фасками, мало органики и износа (износ — задача материалов TASK-008); ноги относительно коренастые; руки висят прямо;
из бюджета в 450 тыс. треугольников использовано 12 % — деталей можно добавлять. Голова небольшая и утоплена между плечевыми
башенками — по замыслу §23, но сверху её почти не видно.
