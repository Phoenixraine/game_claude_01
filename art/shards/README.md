# art/shards — библиотека осколков, щебня и обломков (TASK-016)

Лёгкие меши для инстансинга в Unreal: бетонные осколки 4 размеров, плиты и колонны с арматурой, стекло, галька и щебень, сталь, трубы, кабели, куски фасадов, кондиционеры, вывески — и **20 шаблонов раскола** куба 1×1×1, которыми разрушаются здания.
Направление: `docs/art/DESIGN_BIBLE.md` п.4, эталон — `docs/art/refs/ref05_building_collapse_cockpit.png`. Данные реакций (число осколков, бюджеты) — `data/damage_fx/` (TASK-022).

**Геометрия строится в чистом numpy** (`lib/geom.py`, `lib/builders.py`) — без Blender. Blender (`bpy`) нужен только для экспорта FBX/GLB и превью. Всё детерминировано (сидированные строковые ГПСЧ, целочисленный хэш-шум, без системного времени).

## Запуск
```
python3 art/shards/build_shards.py                  # всё: сборка, проверки, манифест, паттерны, FBX/GLB, превью (~12 мин, Cycles на CPU)
python3 art/shards/build_shards.py --no-previews    # без рендера (~15 с)
python3 art/shards/build_shards.py --previews-only [--only=sheet_gravel.jpg,scene_rubble_pile.jpg]
python3 -m unittest discover -s art/shards/tests    # тесты (чистый Python + numpy, без bpy; ~30 с)
```
Нужны: Python 3.11, `numpy`, для экспорта/превью `bpy` (pip-модуль `bpy`, проверено на 5.0.1) и `Pillow`; для `fracture_patterns.png` — `matplotlib`.

## Контракт
* Имена — как в таблице выше (суффикс `NN` с нуля); `UCX_<Имя>_00` — выпуклая коллизия для L/XL осколков, плит и колонн; для мелких — сфера `radius` из манифеста.
* **Единицы:** 1 ед. = 1 м (метры, FBX без масштабирования), +Z вверх, правая система (Blender); FBX: forward −Y, up +Z. **Пивот = центр масс** (объёмный для замкнутых мешей).
* **Слоты материалов** (в этом порядке по имени): `M_Concrete_Old`, `M_Fracture`, `M_Glass_Shard`, `M_Steel_Rust`, `M_Rebar`, `M_Gravel`. Шейдеры в наборе — только процедурные «для превью»; настоящие материалы — в Unreal.
  Бетонный осколок имеет ровно одну грань «старой поверхности» (`M_Concrete_Old`, самая большая грань исходной выпуклой формы), остальное — `M_Fracture`. Кабели (`Cable_Dangling`) используют слот `M_Rebar` (тёмная сталь), отдельного слота под кабель в ТЗ нет.
* **UV:** один набор `UVMap` в [0,1]; острова не перекрываются (проверяется тестом), каждая грань осколка — отдельный остров с плотностью ≈ метры, трубы/арматура развёрнуты по длине.
* Сглаживание: рёбра острее ≈ 22° (60° для гальки) жёсткие — в FBX это `smoothing groups by edge`.

## Шаблоны раскола (`fracture_patterns.json`)
Куб 1×1×1 с центром в (0,0,0), +Z вверх, фасад смотрит в **−Y**. 20 наборов: `voronoi_08/12/16/24/32_relaxed/40_raw`, `radial_center/offset/low/wide` (радиально-ударный, центр у фасада), `layers_3/4/5/6_fine` («блины» этажей), `diagonal_20_shear/35/50/60_fine` (диагональные полосы), `columns_vertical`, `beams_horizontal` (анизотропный Voronoi). Своя реализация: 3D-Voronoi через отсечение выпуклых ячеек полупространствами (`lib/fracture.py`), ячейки разбивают куб без зазоров (сумма объёмов = 1, проверяется тестом).
Каждый шаблон содержит:
* `cells` — точная геометрия ячеек (вершины + полигоны, `outer` — грань на поверхности куба): можно резать меш здания по ним;
* `pieces` — подмена ячеек библиотечными осколками: `{lib, pos, quat (x,y,z,w), scale, extents, volume, outer_faces}`. Осколок `lib` (в натуральном размере, пивот в центре масс) поворачивается на `quat`, масштабируется **по своим локальным осям** на `scale` (главные размеры осколка → размеры ячейки) и ставится в `pos`. Всё в координатах единичного куба: для здания умножь `pos` и `extents` на размер ячейки. Класс осколка (S/M/L/XL) выбран по размеру ячейки при условной стороне куба 6 м (`mapping_cube_size_m`), форма — по соотношению сторон; грань «старой поверхности» разворачивается к внешней грани куба.

## Проверки (`lib/checks.py`, `tests/test_shards.py`)
Имена и число вариантов (8–12 на размер бетона, 30 галек); бюджет треугольников (≤ 1 500 на меш, ≤ 300 000 всего; 40–400 для бетона, 20–60 для гальки, 30–80 камней в кластере); размеры (S 0.25–0.6 … XL 4–10 м, стекло 2–40 см); конечность координат, отсутствие вырожденных и «встречных» (внутренних) треугольников; **бетонные осколки герметичны** (каждое ребро ровно у двух треугольников, объём > 0); пивот в центре масс; UV в [0,1] без перекрытия островов; выпуклая UCX; детерминизм (повторная сборка = тот же манифест); сумма объёмов ячеек шаблонов = 1, ячейки выпуклые и внутри куба, кватернионы единичные, `scale × pca_extents осколка = extents ячейки`; закоммиченные `shards_manifest.json` и `fracture_patterns.json` = результат генератора. Дополнительно `build_shards.py` прогоняет `mesh.validate()` Blender по всем 178 мешам.

## Ограничения (честно)
* Куски — «правдоподобные выпуклые обломки с рваными гранями» (отсечённый эллипсоид + шум), а не результат симуляции разрушения; без текстур, только UV и слоты.
* В превью «куча обломков» — разброс по холму, не физика; свет и туман для настроения, это не эталон материалов.
* Мелкая галька (24–52 треугольника) — угловатая/гладкая по флагу, без нормалей из высокополигональной модели.
* FBX/GLB не импортировались в Unreal (его нет в облаке): проверены структурой, `validate()` Blender и повторным чтением. Возможные подвохи импорта — смена осей Y между Blender и Unreal; `UCX_` работают по имени (`UCX_<Имя>_00`).
* Фасадные панели — решётка из выпуклых блоков, обрезанная случайными плоскостями (рваный контур), без внутренней арматуры и без стекла в окнах.
